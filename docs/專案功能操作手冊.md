# WeeklyMind 專案功能操作手冊

## 1. 專案定位

WeeklyMind 是一個以 LINE 為主要互動入口的個人自律管理系統。使用者可以：
- 在後台管理計畫與里程碑
- 透過 LINE Bot 打卡與回報
- 接收每日任務提醒與週報
- 使用連結收藏、覆盤中心等已解鎖功能
- 以訪客模式瀏覽畫面，但需要登入才能操作寫入

---

## 2. 啟動方式

### 2.1 啟動資料庫

```bash
docker compose up -d
```

PostgreSQL 預設使用 Docker 容器，對外 port 為 5434。

### 2.2 啟動後端

```bash
cd server
npm install
npm run dev
```

後端預設 port 為 4000。

### 2.3 啟動前端

```bash
npm run dev
```

前端預設 port 為 5173。

### 2.4 一次啟動全部

```bash
npm run dev:full
```

## 3. 登入模式總覽

### 3.1 訪客模式

- 可直接進入 `/app/*` 觀看狀態
- 不會真的打後端查詢需要登入的 API
- 若點擊新增 / 刪除 / 編輯等操作，會顯示登入提問

### 3.2 LINE 加好友即註冊登入

- 使用者加好友後會觸發 webhook
- 後端 `upsert User { lineUserId }`
- 不需要前端登入頁

### 3.3 LINE Login 網站登入

- 使用者在前端點「使用 LINE 帳號登入」
- 後端導向 LINE OAuth
- 授權後回到 `/login/line-callback`
- 前端存 JWT 後進入後台

### 3.4 已停用的手機驗證碼登入

- 後端 API 保留，前端已拔除
- 不再為正式流程

## 4. 功能列表與操作入口

### 4.1 計畫中心

功能：
- 新增計畫
- 編輯計畫內容
- 刪除計畫
- 查看里程碑
- 設定今日打卡

入口：
- 前端側邊欄：計畫中心
- API：`GET /api/plans`、`POST /api/plans`、`PATCH /api/plans/:id`、`DELETE /api/plans/:id`

初始狀態：
- 新使用者沒有計畫
- 需自行新增第一筆，才可能解鎖「連結收藏」

反向狀態：
- 訪客不能新增
- 未登入會跳登入提示
- 伺服器 401/403 時顯示錯誤

### 4.2 里程碑

功能：
- 新增里程碑
- 更新進度
- 刪除里程碑

入口：
- 計畫中心相關區塊
- API：`GET /api/milestones`、`POST /api/milestones` 等

初始狀態：
- 沒有資料時顯示空白

反向狀態：
- 未登入時不可保存

### 4.3 臨時待辦事項

功能：
- 新增隨手待辦
- 勾選完成
- 刪除待辦

入口：
- 計畫管理頁「臨時待辦事項」區塊
- API：`GET /api/daily-tasks`、`POST /api/daily-tasks`

初始狀態：
- 空白列表

反向狀態：
- 訪客無法新增

### 4.4 多益英文

功能：
- 顯示單字進度
- 項目打卡
- 考試日期
- 任務列表

入口：
- 側邊欄：多益英文

初始狀態：
- 畫面可能為空白設定值

反向狀態：
- 未登入時資料不會載入

### 4.5 運動

功能：
- 新增分類標籤
- 新增運動待辦
- 記錄跑步 / 卡路里等打卡

入口：
- 側邊欄：運動
- LINE 訊息：例如「跑了5公里」

初始狀態：
- 沒有分類時空白

反向狀態：
- 未登入不能操作
- 不合法文字會退回 fallback

### 4.6 連結收藏

功能：
- 新增連結
- 自動分類 IG / Threads / FB / other
- 顯示縮圖和資訊

入口：
- 側邊欄：連結收藏
- API：`GET /api/links`、`POST /api/links`

初始狀態：
- 空白狀態，需先解鎖

解鎖條件：
- 新增第一個計畫後，自動解鎖 `links_unlocked`

反向狀態：
- 未解鎖時後端回 `FEATURE_LOCKED`（403）
- 前端會切到鎖定畫面

### 4.7 覆盤中心

功能：
- 檢視進度表
- 看本週達成率
- 查看各分類占比圖表

入口：
- 側邊欄：覆盤中心
- API：`GET /api/retro`

初始狀態：
- 鎖定畫面

解鎖條件：
- 累積打卡次數達到 5 次

反向狀態：
- 未達門檻時直接鎖住

### 4.8 作品集看板

功能：
- 新增專案卡片
- 移動工作狀態
- 更新進度資訊

入口：
- 側邊欄：作品集看板
- API：`GET /api/portfolio` 等

初始狀態：
- 空白看板

反向狀態：
- 未登入時無法新增

### 4.9 設定

功能：
- 個人資料設定
- 主題顏色設定
- LINE / Bot 設定

初始狀態：
- 讀取登入使用者資料

反向狀態：
- 未登入時無法修改

## 5. LINE Bot 互動功能

### 5.1 關鍵字打卡

以下為現實際支援的判斷：

- 貼網址 → 自動存到 `SavedLink`
- 「跑了5公里」→ 寫入 `SportLog`
- 「背了20個單字」→ 寫入 `ToeicProgress`
- 「學了 Vue」/「看了 React」→ 寫入 `DailyTask`
- 「任務」→ 回傳每日任務卡
- 其他文字 → fallback 隨機回覆

### 5.2 自動推播

排程在 `server/src/services/reminder.ts`：

- 每日 08:00：發送每日打卡提醒
- 每週五 21:00：發送本週回顧

設定項目：
- `DAILY_CHECKIN_CRON`
- `DAILY_CHECKIN_TIMEZONE`
- `WEEKLY_REPORT_CRON`
- `WEEKLY_REPORT_TIMEZONE`

## 6. 解鎖機制

解鎖邏輯位於 `server/src/lib/achievements.ts`。

目前解鎖項目：
- `links_unlocked`：新增第一個計畫
- `retro_unlocked`：累積打卡次數達 5 次
- `theme_unlocked`：累積打卡次數達 15 次

判斷時機：
- 新增計畫
- 今日打卡
- LINE 訊息處理完成後

反向狀態：
- 已解鎖則不重複寫入
- 沒有 LINE 帳號則不送 push 通知

## 7. Vercel 觸發打卡請求 API

後端已提供對外的外部 cron 入口：

```http
POST /api/cron
```

### 7.1 內容範例

```bash
curl -X POST http://localhost:4000/api/cron \
  -H "Content-Type: application/json" \
  -H "x-cron-secret: replace-with-random-secret" \
  -d '{"kind":"daily"}'
```

### 7.2 參數

- `kind`: `daily` 或 `weekly`
- `x-cron-secret`: 若 `.env` 設定了 `CRON_SECRET`，就需要帶上此 Header

### 7.3 兼容 Vercel 的觸發方式

如果前端部署在 Vercel，而後端在 Railway/Supabase（或另外的主機），可以在 Vercel 的 Cron / GitHub Action / 外部 scheduler 這類服務每隔一段時間觸發：

```bash
curl -X POST "$VERCEL_URL/api/cron" \
  -H "x-cron-secret: $CRON_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"kind":"daily"}'
```

> 這個入口本身不是用 Vercel 內建 cron，而是讓外部排程器安全地呼叫後端 API。對應程式會在 `server/src/routes/cron.ts`。

## 9. 常見問題

### 9.1 無法連線到後端

確認：
- `server` 是否已經啟動
- port 4000 是否被佔用
- `DATABASE_URL` 是否正確

### 9.2 LINE 登入按鈕顯示尚未設定

需設定：
- `LINE_LOGIN_CHANNEL_ID`
- `LINE_LOGIN_CHANNEL_SECRET`
- `LINE_LOGIN_REDIRECT_URI`

### 9.3 沒有收到每日任務推播

確認：
- `lineUserId` 是否存在
- `DAILY_CHECKIN_CRON` 是否正確
- 後端是否有啟動 `startDailyCheckinReminder()`

### 9.4 連結收藏 / 覆盤中心被鎖住

先完成：
- 新增第一個計畫（連結收藏）
- 累積 5 次打卡（覆盤中心）

---

## 10. 建議的實際運作順序

1. 啟動 Docker + 後端 + 前端
2. 新增 LINE Login Channel
3. 用 LINE 帳號登入
4. 新增第一個計畫，解鎖連結收藏
5. 進行打卡，累積紀錄
6. 觀察每日提醒是否發送
7. 在後端使用 `/api/cron` 測試手動觸發
